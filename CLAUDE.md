# GTM workspace for Claude Code

This folder is a ready-made Claude Code workspace for outbound GTM workshops. It connects the team's CRM (any, or none), a list tool (Clay) and an outreach tool (Lemlist) through Claude, and can run the whole loop on made-up sample data first (safe mode). Teams with other tools plug them in through CSV files (see `revenue-engine`, "Step contracts"). This workshop's settings are in `event.md`. The same skills run in Codex (`AGENTS.md`).

## At the start of every session

- Folder check, before anything else, setup included: the folder this session was started in (the working directory Claude Code showed at start, before any `cd`) must contain `CLAUDE.md` and `.mcp.json` (`ls "<start folder>/CLAUDE.md" "<start folder>/.mcp.json"`; PowerShell: `Test-Path "<start folder>\CLAUDE.md", "<start folder>\.mcp.json"`). Check the files, don't compare path strings (`C:\` and `/c/`, `/private/var`, letter case and worktrees all differ as text). A `cd` into the workspace does not fix a wrong start: the Lemlist server, the permission gates and the Clay plugin load only at start. If the check fails (most often the session was opened on the parent folder, or Claude cloned the repo into a subfolder of the current session), stop and say: "This session is open on `<start folder>`, not on the workspace `<folder>`. The Lemlist server, the permission gates and the Clay plugin only load when the session is opened on the workspace itself. Start a new session on `<folder>` (Desktop app: quit fully and reopen on that folder; terminal: `cd <folder>` then `claude`; claude.ai/code: a new session with this repository selected), then type `set me up`." Until then ask no setup question, write no file, run no tool CLI (`clay`) and call no connector, even if the user asks to carry on here: explain what is missing and offer only to answer questions.
- If `team-profile.md` does not exist or says `setup: incomplete`, or the user says "start", run the `gtm-start` flow (demo, about you, connect, pick use cases, run); its discovery and connect steps are the `hackathon-setup` skill, which runs before anything else. If the user asks for safe mode, a test run or a demo on sample data first, run `revenue-engine` in safe mode (no setup needed), then offer setup. If the user's first message was a request, do it right after setup.
- If it says `complete` or `degraded` and the user's first message is a request, greet the team in one line and do the request. Otherwise greet the team by name in one line and offer the three most useful next steps for where they are and what their stack allows (see `SKILLS.md`); until the team has run a step on its own data (no `out/run-log.md` line outside `workshop |`) and hasn't declined the demos (`menu: declined` in `out/workshop/state.md`), one of them is "see a guided demo on sample data first". When the user asks what Claude can do or isn't sure where to start, and no task is in progress, show the `workshop` menu (not a list of connector features): never make them type a command. If `team-context.md` doesn't exist yet, or is still the website draft from setup, one of the three is "make it ours" (5 to 10 minutes: tone, words to avoid and the team's own trigger phrases).
- New machine check: if `team-profile.md` names a different `os` or `login` than this machine shows, or the user gives a different team name, say so in one line. Re-verify each tool marked connected (sign-ins are per laptop) before using it, and never overwrite another team's profile without asking.
- Requests often arrive as one dictated sentence. Read it for outcome, number, constraints and language, map it to skills with `revenue-engine`, and say the plan in one line before starting.
