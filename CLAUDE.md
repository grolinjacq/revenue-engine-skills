# GTM workspace for Claude Code

This folder is a ready-made Claude Code workspace for outbound GTM workshops. It connects the team's CRM (any, or none), a list tool (Clay) and an outreach tool (Lemlist) through Claude, and can run the whole loop on made-up sample data first (safe mode). Teams with other tools plug them in through CSV files (see `revenue-engine`, "Step contracts"). This workshop's settings are in `event.md`. The same skills run in Codex (`AGENTS.md`).

## At the start of every session

- Folder check, before anything else, setup included: the folder this session was started in (the working directory Claude Code showed at start, before any `cd`) must contain `CLAUDE.md` and `.mcp.json` (`ls "<start folder>/CLAUDE.md" "<start folder>/.mcp.json"`; PowerShell: `Test-Path "<start folder>\CLAUDE.md", "<start folder>\.mcp.json"`). Check the files, don't compare path strings (`C:\` and `/c/`, `/private/var`, letter case and worktrees all differ as text). A `cd` into the workspace does not fix a wrong start: the Lemlist server, the permission gates and the Clay plugin load only at start. If the check fails (most often the session was opened on the parent folder, or Claude cloned the repo into a subfolder of the current session), stop and say, after one line of welcome to the workshop: "This session is open on `<start folder>`, not on the workspace `<folder>`. The Lemlist server, the permission gates and the Clay plugin only load when the session is opened on the workspace itself. Start a new session on `<folder>` (Desktop app: quit fully and reopen on that folder; terminal: `cd <folder>` then `claude`; claude.ai/code: a new session with this repository selected), approve the Lemlist server and the Clay plugin when asked, then type `set me up`." Offer nothing else in this message: never safe mode, which is a host test. Until then ask no setup question, write no file, run no tool CLI (`clay`) and call no connector, even if the user asks to carry on here: explain what is missing and offer only to answer questions.
- If `team-profile.md` does not exist or says `setup: incomplete`, or the user says "start", run the `gtm-start` flow (about you, connect, first campaign, more use cases); its discovery and connect steps are the `hackathon-setup` skill, which runs before anything else. Safe mode (`revenue-engine`, on `samples/`) is a test of the workspace for hosts: run it only when the user types `safe mode`, "test run" or "dry run", and never offer it to attendees (the host shows the demo live). If the user's first message was a request, do it right after setup.
- If it says `complete` or `degraded` and the user's first message is a request, greet the team in one line and do the request. Otherwise greet the team by name in one line, say where they are in `gtm-start`'s fixed order ("The order") and what that step is for, and propose that next step as A, with free text always welcome (`gtm-start`, "How you talk"). Every message in this workspace follows "How you talk" too: at most 150 words outside tables, and a last line that says what to type and names the next step. Never ask the user to choose which step comes first, and never offer a list of unordered options. When the user asks what Claude can do or isn't sure where to start, and no task is in progress, offer `start` and those next steps (not a list of connector features): never make them type a command. With `mode: safe`, never describe the workspace by what is switched off: A is to do it for real on their company ("works on your real accounts, not the samples"). Tone and words to avoid ("make it ours") are inferred from the website during About you and confirmed with one question at campaign step 6, never offered as a separate step.
- New machine check: if `team-profile.md` names a different `os` or `login` than this machine shows, or the user gives a different team name, say so in one line. Re-verify each tool marked connected (sign-ins are per laptop) before using it, and never overwrite another team's profile without asking.
- Requests often arrive as one dictated sentence. Read it for outcome, number, constraints and language, map it to skills with `revenue-engine`, and say the plan in one line before starting.
